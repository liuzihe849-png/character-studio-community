# 把仓库交给 AI 安装

## 验收目标

让当前用户在自己的电脑浏览器里打开完整编辑器，看到且仅看到7套模板；能创建副本、修改、保存和导出。AI连接属于用户自选项，不是启动编辑器的前置条件。

## 执行顺序

1. 在用户指定位置clone本仓库；确认Python3.10+和浏览器可用。缺Python时提供对应系统的官方安装方式，不擅自修改系统Python。
2. `python3 setup.py`（Windows可用`py -3 setup.py`）创建`.venv`、安装依赖并运行环境检查。
3. 用虚拟环境Python运行`python -m unittest discover -s tests -v`。
4. 用虚拟环境Python运行`start.py`。从终端读取实际URL，不假定端口永远是8895。
5. 在浏览器核对：完整编辑器、新建作品、对话、模板库7项均存在；换一个模板会创建副本。
6. 选择一个模板，修改字符/速度，等待保存，刷新后恢复；导出PNG和MP4，检查画幅与时长。
7. 若用户需要AI，选择其本机Codex或自备API。确认使用的是用户自己的账户；不要复制当前AI宿主或作者的登录文件。
8. 使用一条不修改作品的连接测试，再用经用户要求的具体编辑验证工具调用。需要看图的请求检查真实截图，不能只读参数。
9. 交付启动命令、URL、数据位置和停止方法。没有完成的平台或账号测试要明确注明。

## 文件结构

- `web/`：完整前端与7套只读种子模板，供每次启动同步到用户数据目录。
- `src/`：本机服务、受控AI编辑、参考图处理、参数校验与备份逻辑。
- `start.py`：独立用户数据准备和启动入口。
- `setup.py`：创建独立虚拟环境并安装依赖。
- `tests/`：不需要真实AI密钥的检查。

不要上传用户数据目录；不要把Mac编译组件当Windows通用程序；不要仅将本仓库放到GitHub Pages后宣称完整后台已经运行。
